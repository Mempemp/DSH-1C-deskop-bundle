# 0.2.2-rc.1-2

## Правила 1С в проекте

В проект разворачивается один набор правил: `AGENTS.md`, одиннадцать плейбуков в
`.dsh/rules-own/` (поиск, платформа, ИТС, код, запросы, правка модуля, метаданные,
отчёты на СКД, формы, база, ревью), `USER-RULES.md` и `.dsh/1c-rules.json` со
списком разложенных файлов и их хешами.

Предметная часть — неявные транзакции и порядок захвата замков, индексирование
временных таблиц, `ВЫРАЗИТЬ` для составных типов, расширения с `&ИзменениеИКонтроль`,
проектирование регистров, отчёты на СКД, асинхронность 8.3.18, модуль формы —
изложена под инструменты сборки: `rlm`, справку платформы, `v8std`, ИТС.

Таблица инструментов в `AGENTS.md` перечисляет всё, что доступно агенту в сборке:
справку платформы (`1c-platform-context`), знания `v8std`, ответы ИТС
(`1c-naparnik`), поиск и страницы в интернете (`web_search`, `web_fetch`),
браузер (`browser_*`), память (`engram`) и проверки кода (`1c-bsl-checks`).
Поиск вне выгрузки описан отдельным разделом плейбука: справка платформы, стандарты,
форумы, страницы за входом.

`USER-RULES.md` — шаблон из трёх заголовков, куда вклеивается прежний `AGENTS.md`
проекта.

## Проверки кода

Профиль правил проекта — единственный фильтр: включённое правило приходит и при
проверке файла, и при проверке фрагмента. Уровни — `error`, `warning`, `info`,
`hint`, как их отдаёт анализатор. Находки уровней `info` и `hint` доходят до агента
наравне с `error` и `warning`.

Правила, которые анализатор держит выключенными по умолчанию (15 штук, среди них
`TernaryOperatorUsage`, `Typo`, `BadWords`), включаются профилем проекта: плагин
кладёт `<каталог выгрузки>/bsl-analyzer.toml` с нужным набором и удаляет файл, когда
включать нечего. Свой файл без метки плагина остаётся нетронутым.

## Движок анализа кода (rlm)

Сервер `rlm-tools-bsl` поднимается вместе с приложением. После падения процесса он
восстанавливается сам: паузы 3, 8 и 20 секунд, три попытки. Адрес в менеджере MCP
остаётся рабочим, причина падения видна в карточке сервера и в его логе.

## Обновление

Установщик ставится поверх прошлой версии. Проекты открываются со своими
параметрами: `.dsh/1c-project.json` не трогается, развёрнутые правила обновляются
при нажатии «Развернуть правила» — файлы, которые вы правили, остаются вашими.
