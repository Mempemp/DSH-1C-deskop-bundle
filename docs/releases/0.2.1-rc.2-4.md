# DSH для 1С 0.2.1-rc.2-4

Ядро `@deepseek-ai/dsh` 0.2.1-rc.2. Сборка про индекс кода и редактор: индекс переехал на движок
1.47.0 и требует полной пересборки, карточка индекса перестала врать про «устарел» и научилась
объяснять отказы, редактор работает с git, которого в системе может не быть, а сервер справки
по API платформы обновлён до последнего релиза.

## Индекс кода: движок rlm-tools-bsl 1.47.0

Движок ставит установщик (Python-пакет через uv) — 1.46.0 заменён на **1.47.0**.

**Нужна полная пересборка индексов: схема выросла до v18.** Релиз про то, что индекс наконец видит
то, что выгрузка называет явно: перехваты событий и команд форм расширений, тип реквизита, заданный
набором, команды объектов, журналы документов и критерии отбора, ссылки из форм, обращение через
`Метаданные`, вызов с переносом строки, таблицы движений БГУ и объявленные движения документов.
Раньше на всё это был уверенный пустой ответ — «перехватов нет», «ссылок нет», «вызывающих нет» — и
без признака неполноты.

Что это значит на практике:

- Старый индекс продолжает работать. `rlm_start` предупреждает и перечисляет, чего в нём нет, а
  первый `rlm-bsl-index index update` пересобирает его целиком — разовая длительная операция на
  каждый проиндексированный каталог.
- До пересборки `find_references_to_object` и `find_code_usages` называют недоступные виды ссылок в
  `_meta.kinds_unavailable`, а живые маршруты (без индекса) отдают исправления сразу.
- После пересборки откройте новую сессию: поколение индекса читается один раз, при её открытии.
- Несовместимые ответы у перехватов расширений: `get_overrides`, `find_ext_overrides`,
  `read_procedure(..., include_overrides=True)`, а на индексе — `extract_procedures(...)['overridden_by']`,
  `get_object_modules(...)['modules'][i]['overrides']` и профиль модулей. Появились ключи `form_item`
  и `form_event`, у строк из аннотаций они `None`. Счётчики перехватов растут заметно: на ERP с
  расширениями — на 14–15 % строк, на БГУ — на 50 %.

## Параметры проекта 0.10.0: карточка индекса не врёт про «устарел»

- **Автообновление не крутится вхолостую.** Статус «устарел: структура изменилась» обновлением не
  лечится: `update` строит дельту по тому, что видит git, а проверка свежести обходит все папки.
  Любой `.bsl` в игнорируемой папке (артефакты прогонов, фикстуры в `.tmp`) оставлял расхождение
  навсегда — карточка запускала `update` при каждом открытии окна и снова показывала «устарел».
  Теперь при этом статусе автообновление не запускается, главная кнопка — «Пересобрать», рядом
  остаётся «Обновить» для дешёвой дельты, а рядом со статусом объяснение: на диске не тот набор
  файлов, обновление его не сверит.
- **Галочка — это намерение, а не состояние.** Флаг индексации читается из параметров проекта
  (`.dsh/1c-project.json`) отдельным быстрым запросом и не зависит от проверки свежести. До ответа
  галочка неактивна и подписана «читаю параметры проекта…», а не показывает «выключено».
- **Карточка не ждёт проверку свежести.** `GET /rlm/index/state` отдаёт состояние из кэша, устаревшее
  обновляет в фоне (карточка показывает «проверяю…» и опрашивает состояние). Таймаут проверки — 60 с
  вместо 10 с; у сборки свой лимит — час. Прогон, убитый по таймауту, больше не читается как
  «index info завершился с кодом -1», а пустой вывод — как «средство индексации не ответило».
- **Папка выгрузки — настройка, а не догадка.** Новый ключ параметров проекта `rlmIndexPath`: что
  индексировать. Пусто — папка проекта; относительный путь считается от папки проекта. Поле есть в
  блоке «Синтаксическая индексация» окна параметров и на шаге выгрузки в визарде.

## 1С-Редактор кода 0.8.0: git без установки в системе

Релиз собирает 0.7.0–0.7.5 в одну версию.

- **git ищется сам**: путь из настроек → комплектная копия в `$DSH_HOME/git` (её кладёт эта сборка) →
  `PATH` → типовые места установки Git for Windows. В настройках видно, найден ли git, его версию,
  откуда он взят и путь к `git.exe`.
- **«Инициализировать репозиторий»** для проекта без git — первый коммит исходного состояния, в том
  проекте, где открыт редактор.
- **«Обновить дерево»** сбрасывает кэши листингов и метаданных: файл, появившийся в папке помимо
  редактора, виден сразу, без перезапуска и новой сессии.
- **Один вызов git за раз**: общая очередь, одинаковые запросы в полёте склеиваются, проверка версии
  идёт в той же очереди. Шесть одновременных запросов статуса на выгрузке в 34 000 файлов дают пик
  один процесс и ноль висящих.
- Предпочитается внутренний бинарник (`ucrt64/bin`, `mingw64/bin`): `cmd/git.exe` — обёртка, из-за
  которой один вызов выглядел в диспетчере как два процесса.
- **Причина отказа приходит словами git**, а не «git status не отработал — подробности в настройках»,
  где подробностей не было.
- Чтение ждёт 60 с, запись (`add`/`commit`/`init`/`apply`) — 15 минут; по таймауту убивается дерево
  процессов. Прежний 20-секундный лимит обрывал инициализацию на выгрузке 1С и оставлял `index.lock`.
- Настройки не пишут «не найден», пока ответа нет — показывают «проверяем…».
- Иконки узлов метаданных читаются в светлой теме.

## Свойства проекта 0.10.1: сервер справки 0.21.5 → 0.23.1

Вендоренный `bsl-context-rs` (MCP-сервер справки по API платформы) обновлён до последнего релиза
апстрима `v0.23.1`; сам плагин не менялся, пересчитана таблица происхождения в `VENDORED.md`.

- **0.22.0.** Счётчик аргументов больше не считает список из одних запятых одним аргументом —
  `ПоказатьПредупреждение(,)` перестал получать ложный `wrong_argument_count`. Предел `source` в
  `validate_module` поднят с 4 до 16 МиБ (в выгрузках есть модули до 8,8 МБ), а предел тела HTTP-запроса
  выражен через предел исходника с запасом на экранирование кириллицы. Молчание проверок глобальных
  вызовов включается только там, где источник умеет вывести владельца: в модулях форм конфигурации
  снова находятся настоящие опечатки (`Сообщит` вместо `Сообщить`) и вызовы несуществующих процедур.
- **0.23.0.** Список зарезервированных слов сверяется с грамматикой `tree-sitter-bsl` (76 из 76, всего
  ловится 80 имён): `Ждать`/`Асинх`, `ДобавитьОбработчик`/`УдалитьОбработчик` больше не проходят как
  имена процедур молча, а `Выполнить`/`Execute` перенесены в `PLATFORM_REJECTED` — платформа их как
  имена отвергает, но ключевыми словами они не являются. Дополнения к справке задаются файлом вместо
  ручной правки кэша.
- **0.23.1.** Имена в lite-индексе нормализуются в Unicode NFC: выгрузки с разложенными буквами
  (типично для macOS) больше не дают ложных `unknown_metadata_object` и `unknown_common_module` с
  уверенностью `high`. **Одноразовое действие:** если в выгрузке такие имена и lite-индекс собран
  прежней версией — пересобрать его (`rebuild_symbol_index` или CLI `bsl-lite-index build`). На
  обычной Windows-выгрузке (NFC) пересборка не нужна: данные всех таблиц совпали до и после правки.

## 1С-Редактор кода 0.8.1: «не git-репозиторий» — состояние, а не ошибка

Исправлен дефект, который видели на новой машине: в настройках раздела «1С-Редактор кода» висело
«Последняя ошибка git — fatal: not a git repository (or any of the parent directories): .git», хотя в
проекте репозиторий инициализировался, диффы работали, а лишних процессов git не было.

- Свежий проект — папка без репозитория, и редактор проверяет её обычным `git rev-parse`: git
  отвечает `fatal: not a git repository` и выходит с кодом 128. Этот ответ попадал в «последнюю
  ошибку», которую показывают настройки. Теперь отсутствие репозитория — состояние папки: настройки
  говорят «В папке проекта нет git-репозитория — инициализация в панели изменений», а панель изменений
  по-прежнему предлагает инициализацию с первым коммитом.
- Ошибка была одна на весь плагин, а не на папку проекта: отказ, случившийся в одном проекте, висел в
  настройках любого другого. Теперь она привязана к папке и снимается, когда та же команда в этой
  папке отработала; настоящие отказы (битый `.git/config`, лок индекса, таймаут) видны там, где
  случились, и по-прежнему словами самого git.

## Индексация: причина отказа в карточке, повторов больше нет

Раньше карточка проекта сообщала про неудачную сборку индекса только код возврата — «index
завершился с кодом 1», по которому невозможно понять, что делать. Причина при этом была известна:
движок её называл, но она оставалась в журнале.

- **Причина видна в карточке** теми словами, которыми её назвал движок, — например: «Формат
  исходников не распознан как cf или edt, и ни одного .bsl-файла в дереве не найдено — индекс
  строить не по чему». Если движок причины не назвал, остаётся код, и это сказано прямо.
- **Бессмысленный отказ больше не повторяется каждую секунду.** Пока индекса нет, карточка
  постоянно спрашивает состояние, и раньше каждая такая проверка запускала новую сборку: за минуту
  набегали десятки прогонов с одной и той же ошибкой. Теперь отказ, который повтором не лечится
  (нет исходников, нет средства индексации, путь не существует), останавливает автосборку до
  перезапуска — карточка объясняет это и предлагает «Пересобрать», а кнопка снимает остановку.
- **Отказы, которые могут пройти сами** (таймаут, занятый файл, ошибка записи), повторяются как
  раньше.

## Обновление с 0.2.1-rc.2-3

Установленная сборка видит обновление по номеру `0.2.1-rc.2-4`. Плагины приезжают тем же
установщиком: сид форсированно ставит все позиции каталога, поэтому старые версии свойств проекта и
редактора заменяются, а движок индекса переставляется на 1.47.0. Пользовательские настройки,
сессии и профиль не трогаются.

Индексы кода после обновления пересобираются не автоматически — см. первый раздел. Lite-индекс
справки нужен только там, где в выгрузке встречаются NFD-имена (обычная Windows-выгрузка — нет).
