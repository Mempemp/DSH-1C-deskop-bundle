# DSH для 1С 0.2.1-rc.2-1

Первая сборка на ядре `0.2.1-rc.2`: визард добавления проекта 1С, git в редакторе из комплекта,
снимок данных перед обновлением и кнопка возврата на прошлую версию.

## Ядро 0.2.1-rc.2

- Приложение переведено на ядро `0.2.1-rc.2` (Cordis 4.0.5). Каталог пересобран под это ядро:
  у каждой позиции проверено, что её хостовые пиры называют линию `0.2.1`, а не точную версию
  прошлого ядра — иначе плагин ставится и молча не активируется.
- `@wingsky-1/dsh-mcp-manager` поднят до 0.2.10 (пин коммита `5a9c12a`): 0.2.9 объявляет точные
  версии ядра `0.2.0-rc.2`, и на новом ядре панель MCP просто не появлялась.

## Параметры проектов: визард и проверка базы

- При добавлении проекта плагин спрашивает, проект ли это 1С, и ведёт по шагам: база и платформа,
  правила 1С, выгрузка конфигурации, итог. Всё введённое пишется в тот же `.dsh/1c-project.json`,
  что и форма настроек, — визард не второе хранилище.
- Кнопка «Проверить подключение» открывает базу внешним соединением `V83.COMConnector` и читает
  `Метаданные.Версия`: платформа авторизуется, база не блокируется, Конфигуратор не запускается и
  на диск ничего не пишется. Проверка работает и до сохранения параметров.
- Плагин `dsh-1c-project-properties` 0.8.2.

## Редактор: git из комплекта

- Git для диффов, индикаторов изменений и кнопок «В индекс» / «Коммит» ищется сам: путь из
  настроек → комплектная копия в `%USERPROFILE%\.dsh\git` → `PATH` → типовые места установки
  Git for Windows. Если git не найден, в настройках «1С-редактор» это написано прямо, и там же
  можно указать путь к `git.exe`.
- Комплектный git — MinGit 2.56.0.3: первый запуск распаковывает его в `$DSH_HOME/git`, ставить
  Git for Windows пользователю не нужно (33,7 МБ архива против 60+ МБ установщика; без Git Bash,
  Perl, справки и переводов — ровно такая сборка едет внутри GitHub Desktop).
- Кнопка «Обновить дерево» перечитывает папку с диска: заново запрашивает раскрытые каталоги и
  узлы, сбрасывает разобранные метаданные и кэш статусов git. Раньше файл, появившийся в проекте
  помимо редактора, был виден только в новой сессии.
- Плагин `dsh-bsl-editor` 0.7.0.

## Индексы кода: RLM

- Движок `rlm-tools-bsl` 1.46.0 умеет держать индекс кода `bsl_index.db`, который строит отдельный
  CLI `rlm-bsl-index`. Плагин теперь ведёт такие индексы по проектам: сборка при старте DSH и раз в
  неделю, вручную, одна задача на проект с таймаутом в час, отдельный журнал `logs/index.log`.
- Включается там же, где всё про проект: в «Параметрах проектов» есть переключатель индексации, а
  сам флаг лежит в `.dsh/1c-project.json` рядом с базой и платформой — файл едет вместе с проектом,
  и второй настройки в другом месте нет.
- Если CLI не найден, плагин так и говорит — «не найден», а не «индекс устарел»: ставится он вместе
  с движком (`uv tool install rlm-tools-bsl`).

## Обновление и возврат на прошлую версию

- Перед установкой обновления приложение снимает копию пользовательских данных: сессии, реестр
  папок, ключи, настройки, серверы MCP, патчи профиля и данные наших плагинов. Копия делается
  после штатной остановки ядра, когда в журналы сессий уже никто не пишет.
- Копии не растят диск без предела: файл, не изменившийся с прошлой копии, связывается с ней
  жёсткой ссылкой, хранятся три последних копии, есть потолок 1,5 ГБ и отказ снимать копию при
  свободном месте меньше 2 ГБ.
- Установщик работающей версии сохраняется при первом запуске, поэтому «Вернуться на версию X»
  работает без сети и без повторной загрузки: установщик берётся из архива и ставится поверх.
- Кнопка возврата появляется на экране восстановления после второго подряд неудачного старта, и
  в меню значка в области уведомлений — там же «Восстановить данные из копии…». Версия, с которой
  пользователь ушёл, перестаёт предлагаться автообновлением; явная проверка обновлений показывает
  её снова.
- Восстановление данных всегда аддитивное: файлы из копии пишутся поверх, созданное позже остаётся,
  а перед восстановлением снимается ещё одна копия текущего состояния.

## Исправления

- Ctrl+C в консольном режиме ядра снова останавливает работу: Electron в этом режиме стартует как
  процесс, игнорирующий Ctrl+C, и такие процессы Windows вообще не уведомляет о нажатии. Раньше
  событие доходило до слушателей только как Ctrl+Break.

## Ограничения, о которых стоит знать

- Установщик не подписан сертификатом: Windows покажет предупреждение SmartScreen.
- Архив установщиков наполняется только для версий, приехавших автообновлением. Если сборка
  ставилась руками, её установщика в кэше нет, и цель возврата появится после первого обновления
  «из приложения».
- Если копию перед обновлением снять не удалось (например, не хватает места), обновление всё равно
  устанавливается — причина пишется в журнал приложения.
- Проверка подключения к базе и визард требуют установленной платформы 1С и работают только на
  Windows.
