# DSH для 1С 0.2.1-rc.2-3

Ядро `@deepseek-ai/dsh` 0.2.1-rc.2. Сборка собирает то, что нашлось на финальных прогонах:
индекс кода включается и собирается сам, у проекта появляется git, `rlm-bsl-index` ставит
установщик, а обновление снимает плагины, которых в каталоге больше нет.

## Обновление снимает ушедшие плагины

Прошлая сборка поставляла отдельный плагин-раннер `dsh-rlm-tools-bsl`. Его движок переехал внутрь
`dsh-1c-project-properties`, но профиль продолжал грузить старый плагин: раскатка умела только
добавлять плагины. Оба владеют `/rlm/*`, второй `apply` падает — и теряет **все** свои маршруты,
включая `/1cprops/*`. Снаружи это выглядело как «параметры проекта сломались»: страница рисуется,
а каждый запрос возвращает 404.

Теперь каталог объявляет ушедшие плагины полем `retired`, раскатка снимает их (`pnpm remove` и
удаление строки из `bundles`) и запоминает состав каталога в профиле, чтобы следующее обновление
сняло следующего ушедшего. Сверка выполняется даже если установка пакетов из registry не удалась:
чистка строк не требует сети.

Первый запуск после установки — это и есть раскатка: приложение поднимется уже без старого плагина.

## Индекс кода (движок внутри «Параметров проектов»)

Движок `rlm-tools-bsl` больше не отдельный плагин-раннер: он переехал в
`dsh-1c-project-properties` 0.9.1 отдельным модулем (`lib/rlm-runner.js`), роуты остались под
`/rlm/*`, каталог настроек и движка — `$DSH_HOME/rlm-tools-bsl`, поэтому уже установленное
Python-окружение переживает обновление.

Что исправлено по сравнению с предыдущей сборкой:

- **сборка запускается сама**: включение галочки «индексировать проект» и открытие карточки
  проекта запускают сборку, если индекса нет. Раньше авто-проход знал только проекты, уже
  попавшие в настройки после первого прогона, поэтому новый проект навсегда оставался
  «индекса нет» без единой попытки;
- **ошибки видно**: карточка показывает время и текст последней неудачной попытки и путь журнала
  `logs/index.log`. Раньше неудачи авто-прогонов уходили только в лог плагина;
- **статус не врёт**: проба сервера берёт имя из `SERVER_NAME` (был `ReferenceError`, молча
  съеденный `try/catch` — версия не подтверждалась никогда), владелец порта определяется по
  дереву процессов, а не сравнением pid (свой python больше не «чужой процесс»), окно холодного
  старта 30 → 60 с. Зелёный статус с красной ошибкой одновременно больше невозможен: живой, но
  не подтвердившийся процесс — янтарное «запущен, но не ответил на пробу».

## `rlm-bsl-index` ставит установщик

CLI индекса — консольная команда пакета `rlm-tools-bsl`, отдельного exe у неё нет. Раньше её
ставил плагин при первом открытии карточки, то есть у пользователя и с сетью в момент клика.

Теперь это делает раскатка каталога при первом запуске:

- `uv 0.13.5` едет в каталоге как `kind: tool`;
- новый вид элемента каталога `kind: python` ставит `rlm-tools-bsl 1.46.0` в
  `%USERPROFILE%\.dsh\rlm-tools-bsl\{tool,bin,python}` — туда, где компонент ищет команду;
- сеть нужна один раз (uv скачивает управляемый Python и колёса); отказ установки — названная
  ошибка элемента в `$DSH_HOME\logs\catalog-seed.log`, карточка индекса отсылает туда же.

## Git: репозиторий создаётся там, где открыт проект

Редактор 0.7.2: кнопка «Инициализировать репозиторий» переехала из общих настроек в панель
изменений — там, где проект открыт и папка названа путём. В общих настройках осталось только
глобальное: найден ли git, путь к `git.exe`, «Проверить снова».

Кнопка создаёт `git init -b main`, локальные `user.name`/`user.email` (если не заданы, глобальный
конфиг не трогается), `.gitignore` с `.dsh/`, `*.cfl`, `*.log` и первый коммит исходного состояния.
Раньше `git init` в коде не было ни одного, и «Папка проекта не git-репозиторий» оставалось без
выхода. А в общих настройках сообщение про папку проекта было бессмысленным: настроек проекта там
нет, и было непонятно, какую папку инициализируем.

Комплектный git (`$DSH_HOME\git\cmd\git.exe`) приезжает как раньше и находится сам.

## Каталог: пропуск источника — это ошибка сборки

- `prepare-1c-catalog.mjs` больше не печатает `CATALOG COMPLETE` и не завершается с кодом 0,
  пропустив источник: теперь `CATALOG INCOMPLETE` и ненулевой код. Ровно этот случай однажды
  собрал каталог без `tools/git`, и никто не заметил.
- Распаковка `kind: tool` и копирование деревьев в дом идут с тремя попытками: `EPERM` от
  антивируса на 82 МБ MinGit — транзиентная ошибка, а не «источника нет».
- Раскатка каталога изолирует элементы: сбой одного дерева больше не отменяет остальные и
  называется по имени в логе и в результате.

## Состав каталога

17 позиций: 12 плагинов, MCP-строка `v8std`, правила 1С (2026.10.21-18e3383d), MinGit 2.56.0.3,
uv 0.13.5 и пакет `rlm-tools-bsl` 1.46.0.

## Установка

Закрыть DSH Desktop перед запуском установщика: при живом процессе мастер открывается и сразу
выходит. Приложение поднимает несколько процессов — закрывать все.
